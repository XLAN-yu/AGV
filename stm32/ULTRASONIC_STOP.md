# 车头超声波停车：20 cm / 30 cm

2026-09-08。已实现 STM32 固件、完成主机测试及 Keil 编译；尚未烧录或完成实车验收。

## 已实现行为

- 有效距离 **≤ 200 mm**：停止所有电机输出、关闭 STBY、清除待执行运动命令，并锁定停车。
- 触发后，距离 **≥ 300 mm** 且读数保持新鲜至少 **500 ms**，才撤销超声波故障；200～300 mm 区间不会解除故障。
- 超过 **250 ms** 没有新的有效测距：以“超声波不可用”停车。无回波既可能是没有近处反射物，也可能是传感器故障，本版统一按距离未知处理。
- 上电默认禁止输出。首次正常测距满足上述恢复条件后，也需要手动解除停车。
- 故障消失不会自动运动：松开使能和摇杆，在 App 中解除急停，收到成功应答后，再重新长按使能控制。距离仍不满足要求时，STM32 拒绝解除。
- 限制覆盖前进、后退、横移、旋转及本地调试电机命令。当前没有“遇障后允许倒退”的旁路。

超声波只看车头方向，不能检测侧面或后方障碍。20 cm 是测距触发阈值，不是保证的刹停距离；传感器离保险杠的距离、采样周期、车速与惯性都会影响实际余量。

## 接线和协议

现有 HC-SR04 接线：PE6 为 TRIG，PE5 / TIM9_CH1 为 ECHO，双方共地。ECHO 接入 STM32 前应使用合适的 5 V → 3.3 V 电平转换或分压。

不改变 UART 帧格式、34 字节 STATUS 载荷、Wi-Fi/BLE 控制消息或 STM32 原有通信超时、物理急停、编码器保护。新增 STATUS 的 fault_code：

| 十六进制 | 十进制 | 含义 |
| --- | --- | --- |
| 0x30 | 48 | 车头障碍停车 |
| 0x31 | 49 | 超声波没有新鲜有效测距 |

停车同时置 estop 锁存位。已有更高优先级硬件故障可能遮盖这里的 fault_code，但输出仍禁止。App 继续使用现有急停/故障显示；本次没有增加专门的中文故障标签或生成新版 APK。

参数位于 `Core/Inc/car_config.h`，状态机位于 `Core/Inc/obstacle_guard.h`，采样新鲜度与电机保护接入位于 `Core/Src/freertos.c`。

## 实车验收清单（待执行）

先架空车轮，使用能稳定产生回波的平整挡板，记录 App 状态、UART 遥测和电机输出。保持原有单一 UART 网关进程，不要同时运行另一个串口控制程序。

| 操作 | 预期 |
| --- | --- |
| 上电，挡板放在 40～60 cm | 输出保持零；新鲜测距持续至少 500 ms 后故障撤销，但急停锁存仍在 |
| 手动解除，低速操作摇杆 | 成功应答后才能重新使能；四轮方向符合当前麦轮配置 |
| 前进时把挡板移到 20 cm 以内 | 电机输出停止，fault_code 为 48（若无更高优先级故障），estop 为 1 |
| 在 21～29 cm 间移动挡板 | 不解除超声波故障，摇杆和解除命令不能恢复运动 |
| 移到 ≥ 30 cm，保持至少 500 ms | 超声波故障撤销；保持摇杆或使能也不能自行恢复运动 |
| 松手、解除、重新使能 | 才能再次控制 |
| 停车状态断开传感器，然后尝试使能 | 最迟在最后有效测距超过 250 ms 后报告不可用，输出禁止 |
| 有障碍时分别发送前进、倒退、横移、旋转 | 所有方向保持停止 |
| 分别通过 Wi-Fi / BLE 测试上述流程 | 两种入口均受 STM32 保护 |
| 断开控制连接、触发物理 ESTOP | 原有通信超时与物理急停仍停止输出，不能被障碍恢复自动解除 |

架空验证通过后再低速落地测量实际停车余量；若 20 cm 不足，应降低车速或提高触发距离。旧 smoke/watchdog 脚本若假设“上电无故障”，需先满足新测距条件并完成显式解除，再按其原有流程验收。
