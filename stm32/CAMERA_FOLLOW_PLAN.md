# 香橙派摄像头跟随与陀螺仪辅助循迹方案

本文件为后续设计建议；本次交付只实现超声波停车，没有部署视觉跟随或自动循迹。

## 摄像头接入

现有香橙派按 Orange Pi Zero 3 考虑，优先使用支持 UVC 的 USB 摄像头。官方文档提供 Linux 下 USB 摄像头、uvcvideo 和 v4l2-ctl 检查流程；实际视频节点不一定为 `/dev/video0`。[Orange Pi 官方文档](https://www.orangepi.org/orangepiwiki/index.php/Orange_Pi_Zero_3)

接入后先执行只读检查：

```bash
lsusb
v4l2-ctl --list-devices
# 将下方节点替换为上条命令实际识别出的摄像头节点
v4l2-ctl -d /dev/video0 --list-formats-ext
```

先以 640×480、15～30 fps 为采集目标，再根据真实帧延迟和 CPU 占用调整；这不是已测得的性能。相机型号、安装高度、朝向和视场角确定后再标定。

## 跟随方案选择

| 方案 | 用法 | 主要代价 |
| --- | --- | --- |
| ArUco 标记跟随，建议先做 | 人或目标携带指定 ID 的标记，小车跟随这个标记 | 必须看见标记，需标定相机并量出标记边长 |
| 人体检测与跟踪 | 无需携带标记，跟随选定的人 | 需要测量板端推理速度；多人交叉、遮挡和目标切换更难处理；普通单目图像不能直接给出可靠绝对距离 |
| 地面线循迹 | 摄像头朝下看黑线/白线，提取偏移与方向误差 | 依赖光照、地面反光及线条可见性 |

OpenCV 提供 ArUco ID 检测和位姿估计；使用相机内参、畸变参数及已知标记边长，可估计相对位姿。[OpenCV 官方教程](https://docs.opencv.org/4.x/d5/dae/tutorial_aruco_detection.html)

建议第一版只跟随一个指定标记：水平偏差控制转向，估计距离偏差控制前进。初始设计可将目标距离设为约 1 m、最大速度设为 0.1 m/s，再经实测调整；离目标过近时停止，不自动倒退。超声波作为独立停车输入，不能把它的最近回波等同于视觉目标距离。

## 保留现有 STM32 安全链路

```text
USB 摄像头 → 香橙派视觉进程 → 控制源仲裁 → 现有网关 → UART → STM32 → 电机
手机 Wi-Fi / BLE ────────────────────┘                  ↑
                                      超声波 / ESTOP / 通信超时 / 编码器保护
```

视觉进程不直接打开 UART。需要在现有网关增加手动/自动控制源仲裁、自动模式显式使能、租约和停止状态；现有单客户端逻辑不能直接当作已经具备完整仲裁。手机停止/急停始终有效，手动接管先停车并取消自动控制权。

视觉仅处理最新帧，使用单调时钟记录真实采集/接收时间，避免重复读取旧帧仍刷新有效期。第一版建议目标丢失或帧龄超过 200 ms 即发送零速度并锁定自动模式；遥测过期、IMU 无效、网关断开或进程异常同样停止。恢复图像后必须重新手动使能，不自动发 CLEAR_ESTOP。已有网关与 STM32 超时保护继续作为后备，不为了视觉延迟放宽它们。

上述 200 ms 是拟定的软件上限，仍需按实际停车距离测定。先只输出图像及建议速度日志，再架空验证丢帧、断相机、遮挡、进程退出、超声波、ESTOP 和手动接管，最后进行低速跟随。

## 陀螺仪可以做什么

现有 MPU6050 驱动用 Z 轴角速度积分得到 yaw；代码已注明没有磁力计，航向随时间漂移。参见 `Core/Src/mpu6050.c` 中的 yaw 更新。

- **直行保向、定角转弯**：使用陀螺仪航向误差控制转向，编码器闭环控制轮速。开机静止估计零偏，标定正负方向，处理 ±180° 跨界；IMU 失效即退出自动运动。
- **沿地面线走**：摄像头或灰度传感器提供“线在哪里”，陀螺仪提供转向反馈和短时稳定。陀螺仪本身看不到线，不能单独完成可靠黑线循迹。
- **记录路线后重走**：编码器与陀螺仪能做短距离航迹推算，但麦轮打滑与 yaw 漂移会积累误差。长时间重复同一路线需要视觉标记、视觉定位或其他外部定位修正。

建议顺序：先超声波实车验收 → 静止 IMU 零偏及轮向标定 → 低速保向/定角 → ArUco 跟随或地面线循迹。高频航向控制适合放在 STM32 内部；香橙派负责视觉目标，保留相同的速度限幅和安全输出门控。是否新增板端航向指令应另行设计版本兼容，不能直接改写现有速度消息的含义。
